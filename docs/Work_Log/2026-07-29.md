## signalfd fork 继承：移除共享状态突变，改为动态队列解析

**涉及文件：**
- `os/src/fs/vfs/file.rs` — `PollWaitQueue` 和 `EventQueueHandle` 增加 `_event_queue: Option<Arc<EventWaitQueue>>` 字段；`queue()` 方法优先使用动态解析路径；`File::read_wait_queue()` 和 `File::read_event_queue()` 增加 SignalFd 动态队列解析。
- `os/src/syscall/process/signal.rs` — 移除 `event_queue: Mutex<Arc<EventWaitQueue>>` 字段、`event_queue()` 和 `rebind_event_queue()` 方法；`SignalFd::new()` 不再接收 `EventWaitQueue` 参数。
- `os/src/syscall/fs/sys_read.rs` — 阻塞 signalfd 读路径改为从 `task.process.signal_event_queue()` 动态解析队列。
- `os/src/task/task.rs` — 移除 clone 路径中的 `rebind_signal_fds` 循环和 `SignalFd` 导入。

**验证：**
- `make kernel ARCH=rv64 PROFILE=normal` ✅
- `make kernel ARCH=la64 PROFILE=normal` ✅

**备注：** 根因：`FdTable::try_clone()` 克隆 `Arc<File>` 而不克隆 inode，fork 后父子进程共享同一 `SignalFd` 对象。旧方案通过 `rebind_event_queue()` 在 fork 时重绑定队列，但该操作会突变共享状态。新方案不存储队列，在等待时从当前进程动态解析，彻底消除共享状态突变。
