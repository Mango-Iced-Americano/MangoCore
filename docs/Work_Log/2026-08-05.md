## 21:48 — smp-fs-net 分支模块化迁移与合并前收口

**Date:** 2026-08-05 21:48 +08:00
**Author:** AI:GPT/Codex + DeepSeek | Human:Pneuma

**Summary:** 将 `origin/smp-fs-net@e3148c39` 中 FS/Net SMP 生产改造迁移到
`codex/smp-develop-integration@b4f5f13c`，手工适配已经演进的 per-CPU scheduler、
WaitQueue 和 MM/TLB 接口。PageCache、file rmap、native/lwext4、网络设备栈、端口
registry、CPU0 poll worker 与相关 uaccess/trap 路径现在使用同一套 SMP 锁序；未复制
源分支的阶段 ledger 和旧测试结论。

**Files:**

- `os/src/fs/page_cache.rs`、`os/src/mm/{address_space,vma,vma_set,filemap,page_fault}.rs` —
  `op_gate`、逐页 data lock、MAP_SHARED rmap 与 VM 锁外 fault/retry。
- `os/src/fs/ext4/`、`os/src/fs/ext4_lwext4/` — canonical inode/目录事务与 lwext4
  跨实例 C 全局门。
- `os/src/net/config.rs`、`os/src/net/socket/inet/common/port/`、TCP/UDP/RAW/syscall —
  per-device stack、单调 route ID、per-netns 端口事务和异步 CPU0 poll worker。
- `os/src/kernel_tests/{fs_smp,fs_smp_fixture,net_smp,probe}.rs` — 双架构真实多核
  FS、端口、route、worker/veth 和 EPOLLET 探针。
- FS/MM/Net/调度/锁序文档同步；未引入源分支私有计划、历史 Work Log 或 cc-codex 文件。

**Integration fixes:**

- `AddressSpace::new()` 收口为直接返回 `Arc`，避免迁移调用方形成 `Arc<Arc<_>>`。
- file rmap 快照保留 `Arc<FileVmaRmap>`，VM 锁内以 `Arc::ptr_eq` 重验，阻断弱注册表
  解锁窗口中的 allocator 地址复用 ABA。
- 静态 poll worker 的堆型 WaitQueue 改用 `spin::Once` 在任务上下文构造；初始化前请求由
  `pending` 保存，IRQ 只发布原子 deferred 状态。
- 非阻塞网络入口改为一次 `poll_now()` 有界 try-lock 扫描；阻塞入口只异步 request，
  WaitQueue 条件闭包不进入 smoltcp。
- `PortReservation` 以 token + socket Weak 身份唯一拥有 registry 条目，Drop 精确释放；
  删除按端口任意删除 peer 的旧清理接口。
- 删除 `ROUTING_BUF static mut`、死的 legacy poll/config 代码、PageCache/Net 测试 hook，
  以及仅供 ktest 读取的 submitted/completed generation。worker 测试改为真实
  veth→AF_PACKET 业务结果，不让测试扩张生产热路径。
- `UdpSocket::local_endpoint()` 恢复为纯状态查询，不再让 `/proc` 或 getsockname
  accessor 隐式触发全设备扫描；网络推进继续由显式 `poll_now()` 或 CPU0 worker 负责。
- route 发布在目录锁内重验“相同栈身份 + ACTIVE 状态”；所有发布失败统一回滚栈内
  binding/socket，不再用 `?` 提前绕过显式 rollback。
- 删除没有仓库内调用者的 lwext4 掉电测试入口；PageCache 后端列表和网络总体报告同步
  到 `FatPageCacheBackend`、`NetDirectory`、`DeviceStackCell` 与 per-netns `PortRegistry`。

**Notes:** 首轮 RV64 build 暴露误把 `ActiveTracker::new()` 改成 const 的迁移错误；
改为只对 NetPollControl 使用 `spin::Once` 后双架构通过。源分支原先让非阻塞 syscall
同步等待 poll completion，会违反 O_NONBLOCK；集成版改为有界 `poll_now()`。本批不处理
FS/Net/Driver 之外的队友职责，不提交，等待人工批准。测试使用本地 cc-codex Runner，
其任务与日志不进入 Git。DeepSeek 最终只读审查未发现 P0/P1；其提出的 endpoint
查询过重、测试钩子与后端文档问题已收口。它推测的 veth 删除/route 发布竞态经人工
复核不成立：发布路径原本已在目录锁内重验栈身份和 ACTIVE，目录摘除后不能再发布；
本轮进一步统一了失败 rollback，使该不变量在控制流上更直观。全局 `retry_armed`
保留为 v1 性能折中，只影响忙栈重试粒度，不影响正确性。

两次中间网络 job 虽然 QEMU 测例本身 9/9、exit 0，但因代码/文档在执行期间继续收口，
Runner 正确报告 `mutation_detected=true`，没有把它们计入有效证据；最终冻结重跑才作为
验收结果。
