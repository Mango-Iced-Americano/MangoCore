## 10:29 — B64 futex requeue waiter 身份

**Date:** 2026-08-02 10:29 +08:00
**Author:** AI:GPT/Codex + DeepSeek | Human:Pneuma
**Tags:** [area:smp, area:task, area:syscall, type:fix, risk:concurrency]
**Mango Gate:** skill loaded=yes; references=debugging-patterns.md

**Summary:** futex 不再借用只保存 TCB 的通用 `WaitQueue`，改由一次注册一个
`Arc<FutexWaiter>` 跟踪 current key 和真实 wake。requeue 先更新 key 再发布到目标队列，
wake 先发布 `woken` 再让任务 runnable，timeout/signal/waitv 按准确 Arc 身份清理，消除
requeue 后错误 SUCCESS、错误 waitv 下标和目标队列活动残留。

  wait/wake/requeue/waitv，并按 Linux 当前实现返回最后一个已 wake 的 waitv 下标。
- `os/src/task/{manager,mod,process,task}.rs` — 删除通用 WaitQueue 的 futex 专用分支，PCB
  构造和 exec 资源替换改用 `FutexTable`。
- `docs/05_process/`、`docs/01_architecture/`、`docs/10_plan/`、`AGENTS.md` — 同步数据模型、
  锁序、不变量和后续边界。

## 09:03 — B63 SysV semaphore/shared-memory ID 生命周期

**Date:** 2026-08-02 09:03 +08:00
**Author:** AI:GPT/Codex + DeepSeek | Human:Pneuma
**Tags:** [area:smp, area:task, area:syscall, area:mm, type:fix, risk:concurrency]
**Mango Gate:** skill loaded=yes; references=debugging-patterns.md

**Summary:** 删除 semaphore 删除路径中可能因 OOM 静默失效的 `removed_ids` tombstone。
等待条件只在同锁已证明 set 存在且操作必须阻塞后进入，ID 又单调不复用，因此后续缺失可
直接判为 `IPC_RMID/EIDRM`。同时把 shared-memory 的饱和 ID 改为 checked 单调耗尽，避免
`shmat` 两阶段登记在极限回绕后命中新段。

  `EIDRM`；`ShmRegistry` 使用 `Option<i32>`/`checked_add`，耗尽返回 `ENOSPC`。

  初次 `EINVAL`/等待后 `EIDRM`、SHM 两阶段身份和 frame `Arc` 生命周期。
