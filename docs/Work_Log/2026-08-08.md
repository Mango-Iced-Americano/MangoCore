### FS/SMP 修复批次 21：消除跨层轮询并修正 rseq 兼容声明

**问题与根因：**
- another_ext4 事务 metadata gate 的瞬时 `EAGAIN` 被 syscall、PageCache 和后端适配层
  分别用 `yield`/固定次数循环重试，既会在 8 核竞争下放大 CPU 消耗，也会让通用
  syscall 出现 another_ext4 专用行为。
- 创建特殊文件和符号链接时，通用 VFS 先发布目录项、再设置最终 uid/gid/mode；后一步
  失败会留下部分成功的对象。
- `rseq` 只登记用户区而未接入任务迁移、信号中止和 cpu_id 更新，却返回成功；SMP 下
  libc 可能据此使用过期 CPU 编号。

**涉及文件与修改：**
- `dependency/another_ext4/src/ext4/{mod.rs,low_level.rs}`、`src/lib.rs`：metadata gate
  释放后发布进度通知，并增加 guard 释放时序单元测试。
- `os/src/fs/ext4_another/`：统一在文件系统适配层等待 metadata gate 的 generation
  变化；truncate、时间戳、namespace mutation、reclaim 和 PageCache backend 复用同一
  事件驱动入口。
- `os/src/fs/page_cache.rs`、`os/src/task/manager.rs`：为 Loading/Writeback 状态增加精确
  通知 WaitQueue；等待前释放 `op_gate`，移除 PageCache 对后端 `EAGAIN` 的轮询。
- `os/src/fs/vfs/{index_node.rs,mount.rs}`：增加通用 `create_with_data_and_attrs()` 与
  `symlink_with_attrs()`，another_ext4 在单个 namespace transaction 内写入最终属性。
- `os/src/syscall/fs/`：普通文件 mutation 恢复为单次 VFS 调用；仅流式 I/O 保留原有
  waitqueue 阻塞语义，不再包含 another_ext4 专用重试或注释。
- `os/src/syscall/process/rseq.rs`：完整 SMP rseq 协议实现前 fail-closed 返回 `ENOSYS`，
  让 libc 使用兼容路径，避免虚假成功。

**验证：**
- Docker 内串行 `make kernel ARCH=rv64 PROFILE=normal`：通过（约 2m27s）。
- Docker 内串行 `make kernel ARCH=la64 PROFILE=normal`：通过（约 2m32s）。
- RV64 `KTEST=waitqueue`：6 passed、0 failed，`[KTEST RESULT: PASS]`。
- RV64 `KTEST=ext4_another`：20 项因没有磁盘 fixture 全部显式 SKIP；该结果只证明测试
  框架正常启动，不能作为磁盘功能通过证据。
- another_ext4 新增 notifier focused test：1 passed。
- another_ext4 全量 library test：137 passed；2 个既有失败
  `commit_flush_failure_never_publishes_or_checkpoints`、
  `direct_range_plan_filters_small_or_oversized_writes` 可单独复现，与 notifier 修改无关。
- `git diff --check`：通过。

**备注：**
- per-page `try_lock_for_write` 的短 CAS 自旋仍存在，它不是本批消除的跨层后端轮询；
  后续 PageCache 状态机迁移需单独评估。
- 完整磁盘一致性和 BuildStorm 正式测试继续暂停，待剩余 develop 分层迁移完成后使用
  fresh pub 镜像回归。

### FS/SMP 修复批次 22：下沉 syncfs 策略并收紧 UserBuffer 错误语义

**问题与根因：**
- `sys_syncfs` 在 syscall 层按 another_ext4、旧 ext4 分支选择同步流程，使 VFS 外围代码
  知道具体后端，并且 another_ext4 的实例级屏障与其他文件系统语义难以统一。
- PageCache 和 another_ext4 的直接 UserBuffer 路径会用描述符长度静默截短请求；写路径
  可能先修改前缀再把一个无效请求当作成功，偏离 develop 的全有或全无契约。
- PageCache 旧测试仍要求在后端 `EAGAIN` 后内部固定次数重试，与批次 21 已明确的错误
  所有权相冲突。

**涉及文件与修改：**
- `os/src/fs/vfs/file_system.rs`、`mount.rs`：增加通用实例级 `FileSystem::sync()` 并由
  MountFS 透传；默认实现仅为尚未迁移实例 registry 的后端保留兼容性全局 flush。
- `os/src/fs/{ext4,ext4_lwext4,ext4_another}/`：三个持久化后端分别实现实例级同步；
  legacy ext4 与 lwext4 先快照各自 cache registry，再在 registry 锁外写回，another_ext4
  复用其 data/metadata/journal/flush 屏障。
- `os/src/syscall/fs/sys_syncfs.rs`：删除所有具体 ext4 类型识别和 another_ext4 专用注释，
  仅解析 fd 所属文件系统并调用 VFS `sync()`。
- `os/src/fs/page_cache.rs`、`ext4_another/inode.rs`：请求长度超过 UserBuffer 时，在加载、
  lease 或 mutation 前返回 `EFAULT`，不再静默截短。
- `os/src/kernel_tests/page_cache_sync.rs`：把旧的后端轮询断言改为“单次调用传播 EAGAIN、
  保留 Dirty、显式后续调用可成功”，并增加短 UserBuffer 不修改缓存状态/内容的回归测试。

**验证：**
- Docker 内串行 `make kernel ARCH=rv64 PROFILE=normal`：通过（约 2m21s）。
- Docker 内串行 `make kernel ARCH=la64 PROFILE=normal`：通过（约 2m34s）。
- RV64 `KTEST=page_cache`：5 passed、0 failed，`[KTEST RESULT: PASS]`；包含 registry 锁外
  写回、后端 EAGAIN 所有权、短 UserBuffer 原子失败以及后端重入测试。
- `git diff --check`：提交前执行。

**备注：**
- legacy ext4 的 UserBuffer fallback 仍先完成用户内存拷贝再进入 inode transaction，避免
  把可能缺页的用户访问带入 inode 锁；不能用表面上的“零拷贝”直接替换。
- 全局 `sync(2)` 仍有具体后端枚举；彻底下沉需要先提供稳定的全局文件系统实例快照，
  与本批 `syncfs(2)` 的单实例语义分开迁移。

### FS/SMP 修复批次 23：全局 sync 改用 BackendLifecycle 快照

**问题与根因：**
- `syncfs(2)` 已在批次 22 下沉到 VFS，但 `sync(2)` 仍直接遍历 legacy ext4 registry 并
  调用 another_ext4 全局函数，syscall 外围仍知道具体后端。
- `FileSystem::sync()` 的默认全局 PageCache flush 会让内存文件系统也扫描全局 registry；
  若直接用于全局逐实例同步，会产生重复扫描和错误的责任归属。

**涉及文件与修改：**
- `os/src/fs/vfs/mount.rs`、`vfs/mod.rs`：增加 `sync_all_backends()`，在生命周期 registry
  锁内只快照 `Arc<dyn FileSystem>`，随后释放锁并逐实例同步；一个后端失败不阻止其他
  后端，保留首个错误用于诊断。
- `os/src/fs/vfs/file_system.rs`：内存文件系统的默认 `sync()` 改为 no-op，持久化后端必须
  显式声明自己的数据、元数据和设备屏障。
- `os/src/fs/fat32/efs.rs`：FAT32 尚无实例级 PageCache registry，故由 FAT 后端自身显式
  保留全局 PageCache flush 兼容路径，而不是由 syscall 或通用 VFS 猜测。
- `os/src/syscall/fs/sys_sync.rs`：删除 legacy ext4 registry 和 another_ext4 类型分支，仅
  调用通用生命周期同步入口；移除已无调用者的 another_ext4 全局 sync 包装函数。
- `os/src/syscall/process/misc.rs`：删除 shutdown 路径中 another_ext4 预关闭、全局
  PageCache flush 和 legacy ext4 枚举的重复阶段，只调用一次通用 backend teardown；避免
  another_ext4 被关闭后又进入全局写回、随后再次关闭。
- `FileSystem::on_umount()` 默认委托 `sync()`；FAT32 因而也在通用 teardown 中完成兼容
  屏障，三个 ext4 后端继续用各自覆盖实现保证 journal/cache/设备注销顺序。
- `docs/03_fs/vfs-core.md`：同步 FileSystem 实例同步及全局生命周期快照契约。

**验证：**
- Docker 内最终串行 `make kernel ARCH=rv64 PROFILE=normal`：通过（约 2m20s）。
- Docker 内最终串行 `make kernel ARCH=la64 PROFILE=normal`：通过（约 2m23s）。
- RV64 `KTEST=page_cache`：5 passed、0 failed，`[KTEST RESULT: PASS]`；关机阶段所有
  filesystem teardown 同时通过（在 shutdown 去重修改后重新构建并运行）。
- `git diff --check`：提交前执行。

**备注：**
- 此批完成了 syscall 同步路径去具体后端化。FAT32 的兼容性全局 flush 仍有额外扫描，
  待其拥有实例级 inode/PageCache registry 后可局部化，不影响当前持久化正确性。
- 未恢复 BuildStorm；继续按既定顺序完成剩余 lifetime/专项测试迁移后再使用 pub 镜像。
