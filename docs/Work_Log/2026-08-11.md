## 07:30 — 双架构 bootstrap heap 8MiB→32MiB，修复大内存启动早期 OOM + 评测产物 strip 发布

**Date:** 2026-08-11 07:30 +08:00
**Author:** AI:opencode/Sisyphus | Human:user
**Tags:** [area:mm, area:build, type:bugfix]

**Mango Gate:** skill loaded=yes; references=debugging-patterns.md（启动/Panic 排查、内存问题）

**Summary:** 评测命令行 `qemu-system-loongarch64 -m 36G -smp 12` 在启动早期（`Console
initialized.` 之后、`init_runtime_heap` 之前）触发 `HEAP ALLOCATION FAILED (FATAL)`：
`layout: size=9356593, align=1`、`KERNEL_HEAP_SIZE: 8335360 bytes`（= 8MiB bootstrap heap）。
根因：`StackFrameAllocator::init` 为每个 DRAM region 创建 `FrameRegion::new()`，其
`recycled_flags: Vec<bool>` 按区域页数 1 字节/页分配。36G LA64 高内存 region 约
9,350,494 帧 → 请求 9.36MiB，buddy 圆整到 order 12（16MiB 连续块）；加上
`laflex::IdentityDirtyMap`（36G 时约 1.19MiB，圆整 order 9），都发生在 runtime heap
建立前，8MiB bootstrap heap 必然失败。修复：双架构 `KERNEL_BOOTSTRAP_HEAP_SIZE`
8MiB → 32MiB（含注释说明 36G 场景的尺寸推导）。RV64 16G 时 flags 需 4MiB，统一 32MiB
留余量。

第二项：评测机只认项目根目录 `kernel-rv`/`kernel-la`，而 `make all` 发布的
`publish-compatibility` 复制的是未 strip 的 110MB debug ELF；RV64 ELF 的 PhysAddr
是链接虚拟地址（0xffffffc0...），QEMU 根本无法加载（`No enough memory to place DTB`）。
修复：rv64 `stage-kernel` 改为发布 strip 后 raw binary（`Image` 同源，10MB）并补上
`kernel` 依赖（此前 rv64 `build` 根本不生成 `kernel-rv`）；la64 `stage-kernel` 改为
`objcopy --strip-all`（110MB→18MB，保留 ELF 格式，PhysAddr=0x80000000 不变，QEMU
仍可加载），并依赖 `$(KERNEL_BIN)` 消除构建竞态。`make all` 的 `publish-compatibility`
仍自动把产物复制到根目录（COMPAT_OUTPUT_DIR=REPO_ROOT）。

**涉及文件：**
- `os/src/hal/arch/loongarch64/config.rs` — `KERNEL_BOOTSTRAP_HEAP_SIZE` 8MiB→32MiB + 尺寸推导注释
- `os/src/hal/arch/riscv/config.rs` — `KERNEL_BOOTSTRAP_HEAP_SIZE` 8MiB→32MiB
- `os/make/rv64.mk` — `stage-kernel` 发布 `$(KERNEL_IMAGE)`（strip raw binary）、依赖 `kernel`；`build` 链补入 `stage-kernel`
- `os/make/la64.mk` — `stage-kernel` 改 `objcopy --strip-all` 输出、依赖 `$(KERNEL_BIN)`

**验证：**
- 双架构 release 编译通过（rv64/la64 各 ~2m47s）
- LA64 12核36G QEMU（用户原始命令）✅ 无 panic，`9415773 usable physical frames across 3 region(s)`，region2=[0x852a2000,0x970000000) frames=9350494，test-runner 跑完
- RV64 8核16G QEMU（`-kernel Image`）✅ 无 panic，region1 frames=4174147，test-runner 跑完
- strip 产物复验：kernel-rv 10MB raw binary、kernel-la 18MB stripped ELF，两架构 QEMU 再跑均无 panic
- 根目录产物模拟 `publish-compatibility`：`kernel-rv`/`kernel-la`/`Image` 就位

**备注：**
- RV64 必须用 raw binary（`-kernel Image` 或新 kernel-rv），不能用 ELF；LA64 用 ELF 或 strip ELF 均可
- 此前 `build` 目标不生成 `kernel-rv`，`publish-compatibility` 直接 cp 会失败（旧产物/缺失）——已通过 `stage-kernel` 入 `build` 链修复
