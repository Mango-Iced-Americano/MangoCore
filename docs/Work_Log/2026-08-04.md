## 00:12 — B82 真实用户 CoW 与同 VPN 重映射 TLB 证明

**Summary:** 扩展 B53 的真实用户 stale-TLB 探针：CPU1 在同一 VPN 上依次观察旧页、CoW
页和 `munmap + MAP_FIXED_NOREPLACE` 重映射页；CPU0 两次修改均走生产
`AddressSpace::write -> MmuGather/TlbFlush -> range shootdown`，不新增生产测试钩子。
首轮 LA64 暴露 `quiesce_local_timer_interrupt()` 只清 TICLR pending、未停止尚未到期倒计时；
按 LoongArch 官方 `TCFG.En` 定义改为先停计数再清 pending，并修正寄存器 wrapper 的反向读取。

**Verification:**

- LoongArch 官方架构手册 V1.10 §7.6.2/§7.6.5 — ✅ `TCFG.En=1` 才倒计时，TICLR 仅清
  timer interrupt flag；据此拒绝仅清 pending 的伪静默。
- DeepSeek max 只读并发审查 — ✅ 同一 VM 写事务内先撤 PTE、安装新 PPN，锁外 shootdown
  收齐 ack 后才释放退休 frame；GPT 复核补上模型遗漏的 remap frame 超时保活。
- 首轮 Docker 双架构 8 核 SMP — RV64 新用例 PASS；LA64 用户探针成功但 timer 隔离后验失败，
  定位为 TCFG 仍倒计时；两架构另有既有 exec identity 5 秒边界失败。
- timer 修复后 Docker 双架构 `CORE_NUM=8 KTEST=smp KREPEAT=1` — ✅ 新用例均 PASS、
  `online_mask=0xff`、无 panic/fatal trap；LA64 不再出现 timer 隔离错误。
- 完整套件两架构均为 33/34：唯一失败仍是
  `smp::exec_owner_becomes_group_leader` 在 5002/5003ms 超时，作为下一 task 节点处理；因此
  本节点定向状态为 pass，完整 SMP suite 状态为 partial，不把进程退出码 0 误记为全量 PASS。

**Notes:** 单次 `AddressSpace::write()` 让旧 TLB 在锁内修改期间仍可合法读取旧页，而解锁后的
同步返回保证下一次用户 load 必须看到新 PPN；退休 frame 在 ack 前由 gather 持有。该证据覆盖
CoW 和 unmap/remap，不覆盖 `mprotect` 降权后的 store fault，也不解除普通用户默认 CPU0 限制。
