### FAT32 簇表变更事务化并补齐双架构 8 核一致性测试

**涉及文件：**

- `os/src/fs/fat32/bitmap.rs` — 把空闲缓存与扫描游标合并进卷级
  `FatMutationState`；allocation 按“候选簇先写 EOC、再链接前驱”发布，free 按
  “保留尾先断链、再 tail-first 写 FREE”回收，完整覆盖一个 FAT 变更事务。
- `os/src/kernel_tests/{fs_fat_smp,probe,mem_block}.rs`、
  `os/src/kernel_tests/ext4/block_device.rs`、`os/src/kernel_tests/mod.rs` — 复用内存块设备，
  在 ktest 内构造合法 67,000 数据簇 FAT32 卷；CPU1/CPU2 用户探针经真实
  `ftruncate` syscall 并发执行整链/后缀 alloc-free，重挂载后检查环、双归属、越界和
  不可达已分配簇。

**验证：**

- DeepSeek 只读审查确认卷级锁覆盖搜索、占用发布、链指针更新和回收缓存，
  `dealloc_clus()` 的 tail-first 输入与 `Fat::free()` 约定一致。
- Docker `CORE_NUM=8` RV64/LA64 normal kernel build ✅/✅（140 s / 145 s）。
- Docker `CORE_NUM=8 KTEST=fs_fat_smp` RV64/LA64 focused ktest ✅/✅（152 s / 148 s）；
  两者均为 1 passed、0 skipped、0 failed，启动日志确认 `online_mask=0xff`。
- `rustfmt --check`（五个本批 Rust 文件）✅；`git diff --check` ✅。focused 门禁后仅按
  rustfmt 建议调整了一处常量表达式换行，没有语义改动，未重复运行 QEMU。

**备注：**

- 首版探针每轮附带 `unlinkat`，LA64 暴露目录删除失败；该操作不经过本批

- 已检查 FAT32 与 ktest 文档组织；本批没有改变生产挂载入口和磁盘布局，无需同步

### 收口整页物理内存引用并实现 per-CPU CPU 时间账户

**涉及文件：**

- `os/src/mm/address.rs` — 删除安全返回 `&'static mut [u8]` 的
  `get_bytes_array()`，以 unsafe scoped `with_bytes[_mut]()` 将 slice 生命期限制在单次调用中。
- `os/src/mm/{address_space,filemap,vma,frame_store}.rs`、`os/src/fs/{ramfs,vfs/file}.rs`、
  `os/src/syscall/process/{clone,ids}.rs` — 按 frame 是否已发布区分 scoped slice 与 raw
  copy；filemap/VMA 初始页改为先填充未发布 frame、再安装 PTE，并增加只针对
  无 PTE frame 的失败回滚。
- `os/src/task/{processor,task}.rs`、`os/src/hal/arch/{riscv,loongarch64}/trap/mod.rs` —
  在 `CpuTaskState` 内累加 user/system/idle 微秒时间；trap return 采用“安全点前结算
  system、恢复汇编前开启 user”的两段边界，idle 快照以 sequence 协议包含未闭合区间。
- `os/src/fs/procfs/files/stat.rs` — 将内部微秒按 Linux `USER_HZ=100` 转换，输出
  aggregate 和每个 configured `cpuN` 的 user/system/idle；暂无独立账户的字段继续为 0。
- `docs/04_mm/address-space-and-vma.md`、`docs/05_process/{scheduler,time-sched-rlimit}.md`、
  `docs/10_plan/smp-8core-implementation.md` — 同步内存发布顺序、计时边界、idle 口径和
  SMP 实施状态。

**验证：**

  `update_process_times_leave_trap` 调用扫描均为空。
