### HAL v2 + FDT 平台抽象重构 — 方案规划与 fdt crate fork

**涉及文件：**
- `.omo/plans/hal-v2-fdt-platform-abstraction.md` — 新增，完整 6 阶段实施方案
- `docs/Work_Log/2026-07-28.md` — 新增，本条目

**背景：**
Oracle 结合 MangoCore 当前代码库做了架构分析，确认以下关键点：
1. `rust_main()` 当前无参数 — entry.asm 丢弃 a0 (hartid) 和 a1 (dtb_paddr)
2. `StackFrameAllocator` 已支持多 region，只需将 `MEMORY_REGIONS` 从 const 改为动态
3. `BootConfig` 已有 `root`/`init` 字段但未接线
4. `devfs` 已支持动态设备节点注册
5. LA64 entry.asm 的 DMW 窗口切换是保存启动参数的**关键风险点**

**方案要点：**
- 6 个 PR：boot 协议 → FDT memory 解析 → PlatformInfo → PlatformPolicy → DeviceManager → root 选择
- 目录结构：`hal/boot/`, `hal/firmware/`, `hal/platform/`, `hal/device/`
- Pre-heap 阶段只解析 memory 节点（无 alloc），post-heap 完整解析 FDT
- 静态回退路径覆盖所有阶段
