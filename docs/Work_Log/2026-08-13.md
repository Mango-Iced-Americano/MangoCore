# 2026-08-13 Work Log

## 修复正式评测负载被限制在 CPU0

- 基线：GitHub `origin/develop@5e92b91b337b5340ee6419db210d1dada65bf5fd`。
- 根因：TCB 的 CPU0-only 初始 affinity 是内核启动阶段的安全默认值；专用
  `profile=buildstorm` 会主动放开 affinity，但正式评测走
  `profile=normal -> PID1 -> test-runner -> CAgent/BuildStorm`，因此 PID1 及
  fork/exec 后代一直继承 CPU0-only mask。根目录正式构建和兼容 judge 配置也仍
  使用单核默认值。
- 修改：
  - `user/src/bin/init.rs`：normal PID1 在启动 test-runner 前调用
    `sched_setaffinity(all)`，失败时 fail-closed；regression 保持原有隔离语义。
  - `os/Makefile`、`judge/config.json`、`judge/run.py`：正式 RV64/LA64 构建固定为
    8/12 核，兼容评测配置不再回退到 1C/1G；并发 QEMU 分别使用独立配置视图，
    避免旧 runner 用一个共享 `qemu.smp` 标量把 LA64 降成 8 核。
  - `scripts/test-canonical-build-graph.sh`：加入正式拓扑与 judge 配置合同门禁。
  - `os/src/{main.rs,smp.rs,task/processor.rs}` 与 `docs/05_process/*`：澄清
    CPU0-only 是 TCB 首次发布默认值，正常用户态由 PID1 显式放开，不改变内核
    工作线程的安全默认值。
- 验证：
  - Docker `make toolchain-preflight`：通过。
  - Docker 串行 `make kernel ARCH=rv64 PROFILE=normal CORE_NUM=8 LOG=off`：通过。
  - Docker 串行 `make kernel ARCH=la64 PROFILE=normal CORE_NUM=12 LOG=off`：通过。
  - Docker `make lint`：RV64/LA64 的 debug/release 四格均匹配 warning 基线。
  - RV64 normal 评测链路发烟：官方 pub x0、8C/8GiB、MTTCG、
    `mode=run mask=0x6000`；OpenSBI 报告 8 hart，内核报告
    `configured=8 online_mask=0xff`，CAgent 与 BuildStorm 两个 test-runner 后代均
    报告 `nproc=8`、`_NPROCESSORS_ONLN=8`、`/proc/cpuinfo=8`。
  - `make -n all`：RV64/LA64 分别向架构构建传递 `CORE_NUM=8/12`。
  - `judge/run.py` 语法编译与架构配置视图单元探针：通过；并发线程分别解析为
    RV64 8C 与 LA64 12C，且不修改共享 job 配置。
- 备注：发烟探针、镜像副本和串口日志位于仓库外临时目录，未纳入提交；
  `/proc/[pid]/status` 当前把 `Cpus_allowed` 写死为 CPU0，不能作为 affinity
  证据，`nproc` 使用的 `sched_getaffinity` 返回真实 TCB mask。
