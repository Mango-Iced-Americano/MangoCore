## 2026-07-18

### ext4_lwext4 融合：2K 字节边界、namespace/inode lifetime 与生产门禁

#### 背景与审计结论

融合目标固定为 `board-develop-combined`。当前基线是双父 merge
`78dd1c8c`，父提交分别为 `la64-on-board@464e24b5` 与
`develop@60800fa2`。

本轮复核 onboard 自研 ext4 的 allocator、目录项、metadata cache、延迟回收、rename
和 PageCache 性能提交后，结论是：旧引擎内部代码不应机械移植到 lwext4；应迁移它们
证明过的平台块不变量、inode lifetime、namespace 失败保全和冷重挂载/fsck 门禁。

当前补丁已改善正常运行语义，并使用 inode generation 隔离运行期对象复用；但 P4 与
QEMU fixture 均无 journal，deferred unlink 仍没有带 generation 的 on-disk orphan chain
或 mount-time replay。因此当前状态是
“融合候选正在验证”，不是“可以生产上 SSD”。

#### 涉及文件

**块设备与挂载边界：**

- `os/src/fs/ext4_lwext4/blockdev.rs` — 将 byte I/O 拆为 partial head/tail bounce 与
  aligned middle multi-block 请求；支持 2 KiB 参数化 ktest。
- `os/src/drivers/block/partition.rs` — 使用 byte offset 支持未对齐 MBR 分区；最后不足
  平台块的分区尾部按精确边界写入、读出时零填充。
- `os/src/fs/mod.rs`、`os/src/syscall/fs/sys_mount.rs` — 按完整 `DetectedFs` 适配设备；
  `BlockSizeAdapter` 只用于 FAT，避免 lwext4 byte bridge 双重缩放。

**lwext4 namespace 与 inode 生命周期：**

- `os/src/fs/ext4_lwext4/inode_state.rs` — 新增真实 inode keyed 共享状态，维护 path、
  logical size、nlinks、open count、pending delete 和持久 `ext4_file` handle。
- `os/src/fs/ext4_lwext4/ext4fs.rs`、`os/src/fs/ext4_lwext4/mod.rs` — 注册/查找/回收
  inode state，并与 PageCache registry 共享真实 inode identity。
- `os/src/fs/ext4_lwext4/layout.rs` — open/close、unlink、rmdir、rename、truncate 和
  PageCache backend 改用共享 handle；same-inode rename no-op；regular overwrite target
  具备运行期 detach/rollback/finalize；dirty cache 错误向上传播。
- `os/src/fs/ext4_lwext4/page_cache.rs` — I/O 不再使用 stale path create fallback，
  rename/unlink 后继续通过 inode handle 访问同一对象。
- `dependency/lwext4_rust/c/lwext4/include/ext4.h`、
  `dependency/lwext4_rust/c/lwext4/src/ext4.c` — 新增 non-recursive
  `ext4_dir_rm_empty`、deferred remove/finalize 和 handle-based relink API。
- `dependency/lwext4_rust/c/lwext4/src/ext4_extent.c` — 修复 truncate/remove range 起点
  落在首 extent 前或 extent 间 hole 时误报成功、泄漏后续物理块；归一化到下一已分配块，
  重建 path，并传播 leaf remove 错误。
- `dependency/lwext4_rust/c/lwext4/src/ext4_bcache.c`、`ext4_fs.c`、
  `ext4_journal.c` — 修复直接写后 stale cache、inode generation 更新、journal/umount
  teardown 重试和 transaction 错误传播；`removexattr` 不再递归获取同一 mount lock。
- `dependency/lwext4_rust/src/bindings.rs`、`dependency/lwext4_rust/src/file.rs` —
  暴露上述 C API 给 Rust 适配层。
- `os/src/fs/page_cache.rs`、`os/src/fs/ext4_lwext4/page_cache.rs` — 以 generation 限定
  cache identity，用 per-inode I/O gate 排序 read/writeback/truncate，避免 readahead 与
  truncate 竞态，并将后端错误向上传递。
- `os/src/fs/vfs/file_system.rs`、`os/src/fs/vfs/mount.rs`、
  `os/src/syscall/process/misc.rs` — `on_umount()` 改为可失败接口；Dying backend 失败后
  保持可重试，正常关机先 PageCache writeback，再提交并脱钩全部文件系统后才 halt。

#### 已知限制与后续门禁

- 当前 P4 和 regression fixture 使用 `^has_journal`；C transaction 不能提供掉电原子性。
- zero-link open inode 没有加入 on-disk orphan chain，掉电可能泄漏 inode/blocks并依赖 fsck。
- `ext4_fremove2(defer=false)` 的 truncate/unlink 顺序仍需收敛为“namespace detach first”。
- empty-directory overwrite 当前在 mutation 前以 `EOPNOTSUPP` fail closed，数据保全但
  POSIX 兼容性不完整；缓存子孙路径、精确 errno、静态 journal feature 报告和设备 flush
  契约仍需处理。
- journal checkpoint 写失败仍可能被 `jbd_journal_purge_cp_trans()` 吞掉；
  `ext4_ext_free_blocks()` 的 `void` 接口仍会吞掉底层 block-free 错误。
- partition sibling 测试当前验证精确顺序和边界，但没有真正制造两个分区并发 RMW 交错。
- SSD 全盘备份已经验证完成，但仍必须先过实板只读身份、journal/orphan 故障注入、真实
  flush、性能 A/B 和受控 scratch 门禁；当前禁止写生产 P4。
- 当前 dirty patch 还需 clean fixture 冷重挂载、focused FS/LTP、实板 2K 只读和新旧
  性能 A/B，才能讨论生产切换。
