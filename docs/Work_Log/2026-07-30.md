### B28 受控 AP 用户态 syscall、yield 与退出回收闭环

**状态：`partial`。** 双架构 8 核 focused 与初赛非回归均通过；仓库既有 lint warning
baseline 仍为 RED，因此不把整个工作包写成 `pass`。本节点只开放一个 hermetic 用户探针，
普通用户任务、affinity/迁移、AP timer 和共享 I/O 仍未开放。

**目标与边界：**

- B27 已完成双架构 MM-owned ASID 和页级 shootdown，但用户 trap handler 仍断言只能在
  CPU0 运行，缺少一条真实用户任务从远程发布、trap-return、syscall/yield 到退出回收的
  动态证据。
- `CPU0 -> AP -> CPU0` 在这里表示 CPU0 创建/发布、CPU1 执行、CPU0 wait/reap；不是同一
  TCB 从 CPU0 迁移到 CPU1 后再迁回。探针不进入 FS、net、VirtIO、console 或设备 syscall。
- AP 仍不开 timer/external IRQ。探针只能在 syscall 受控窗口响应 IPI，调度让出依赖显式
  yield，不把本节点外推为通用 AP 抢占。

**实现与每项修改的原因：**

- `task/manager.rs` 增加唯一 `publish_task_on(task, cpu)`：先验证目标已 online/scheduler-ready，
  远端目标先确认动态 kernel stack 映射，再通过生产 runqueue 状态机发布，最后在队列锁外
  发送 `RESCHEDULE`。这样 kernel-only ktest 与用户探针不再复制三段协议，也不会出现
  “doorbell 先到、任务/栈尚不可见”的竞态；普通 `publish_task()` 仍固定 CPU0。
- `task/processor.rs` 增加 `current_trap_task()`，一次克隆本 CPU current，再在 processor
  锁外校验 `TaskStatus::Running(cpu)`。它取代两架构过时的 CPU0-only 断言；返回型 syscall
  后重新调用并重新读取 CPU ID，为未来 syscall 内 yield 后迁移保留正确语义，同时避免
  trap 热路径为“取 current”和“校验 owner”重复获取同一把锁。
- 双架构 syscall handler 在进入 `syscall()` 前显式 drop 临时 TCB `Arc`。`exit/exit_group`
  切回 idle 后不会返回当前 Rust 栈帧，依赖作用域析构会永久多留一个强引用；返回型 syscall
  再重新取得 current 写回结果。测试最后用 `Weak::upgrade()` 直接验证强引用已经归零。
- `kernel_tests/smp.rs` 内嵌 RV64/LA64 的最小 generic-ABI 指令，仅执行 getpid、yield、exit。
  现有 `/init` 只在 CPU0 被用作成熟的 ELF/用户栈/trap-context 脚手架，fd 在发布前全部关闭；
  指令先装载到 RW 匿名页，再通过正式 mprotect/PTE 提交收紧为 RX，AP 从不执行 W+X 页面。
- CPU0 把探针挂到当前 ktest 父进程后发布到 CPU1，等待 task/process zombie、本地 current
  清空、runqueue 清空和 zombie 交接，再通过 `wait_child()` 回收并核对 exit status。用例
  开始前显式清空旧 zombie，使“队列出现元素”确实对应本探针，而非依赖测试执行顺序。
- 没有新增 TCB/PerCpu 测试字段、TaskStatus、MM wrapper 或测试专用生产发布函数，也没有
  新建用户 ELF 文件。DeepSeek 建议的独立 `/test_ap_user` 和专用 API 因扩大维护面被拒绝。

**事实纠正：**

### B27 RISC-V MM-owned ASID、epoch rollover 与按 ASID 页级 RFENCE

**状态：`partial`。** 双架构构建、RV64 8 核 focused、双架构 8 核初赛非回归均通过；
仓库 lint baseline 已在 B27 之外发生漂移，因此 `make lint` 仍为 RED，不能写成完整 `pass`。

**目标与官方依据：**

- B24 已能把 RV64 单页范围交给 SBI RFENCE，但所有用户 MM 仍固定使用 ASID 0，页级
  flush 无法限定到目标地址空间；trap 每次切换 SATP 也必须全量 `sfence.vma`。
- RISC-V Supervisor 规范规定 RV64 `satp[59:44]` 是 ASID，并要求通过“向 ASID 字段写
  全 1、读回最低有效实现位”探测 ASIDLEN；写 SATP 本身既不隐含页表写入排序，也不自动
  失效旧翻译。页级 non-global 失效应使用 `SFENCE.VMA va, asid`。
- SBI RFENCE FID 2 的 ABI 是 `hart_mask, hart_mask_base, start, size, asid`，第五个参数
  位于 a4；调用同步返回后，目标 hart 已完成等价的地址范围 + ASID 失效。
- Linux RISC-V 的 `context.c` 使用 versioned ASID 与 rollover，全局无 ASID 时退化为
  switch-time flush；`tlbflush.c` 的页/范围失效同样携带目标 MM 的 ASID。MangoCore 沿用
  这些硬件语义，但不复制 Linux 的 per-CPU bitmap/调度结构。

参考：

- <https://docs.riscv.org/reference/isa/v20260120/priv/supervisor.html>
- <https://docs.riscv.org/reference/sbi/v3.0/ext-rfence.html>
- <https://raw.githubusercontent.com/torvalds/linux/master/arch/riscv/mm/context.c>
- <https://raw.githubusercontent.com/torvalds/linux/master/arch/riscv/mm/tlbflush.c>

**实现与可维护性取舍：**

- 没有新增 MM wrapper、commit 类型或源文件。RV64 allocator 直接放进现有
  `hal/arch/riscv/sv39.rs`，长期所有权仍由既有每 MM `TlbContext.asid_context` 承担；
  PTE 生命周期仍只有 `MmuGather -> TlbFlush` 一条提交链。
- BSP 在内核 Sv39 页表生效、AP 和用户任务尚未发布时探测 ASIDLEN。内核永久保留
  ASID 0，用户从 1 单调分配；QEMU virt 实测为 16 bit，即 65535 个用户编号。
- 软件 context 用高位保存 epoch、低 16 位保存硬件 ASID。MM 销毁不立即归还编号；空间
  耗尽后只有一个 CAS leader 执行全 online CPU user-TLB flush/ack，收齐后才推进 epoch
  并从 1 复用。等待者不持 VM 锁，并临时开放本地中断，避免双方等待 TLB IPI ack。
- `AddressSpace::activate_on()` 仍在 VM 锁内成对取得页表根和 ASID；发现耗尽时先释放锁，
  再 rollover 并重试。页表修改方也在同一 VM 锁内冻结 target mask、generation、ASID
  和 VPN，锁外才执行 RFENCE/IPI 和退休 frame。
- 本地页级失效改为 `sfence.vma va, asid-register`；即使 ASID 数值为 0，也让 rs2 使用
  普通寄存器而不是 x0，保留“精确匹配 ASID 0”语义。远端 RFENCE 改用 FID 2，并将 a4
  纳入 `sbi_call_v02`。固件缺少 RFENCE 时仍走 B26 固定 slot 软件 IPI fallback。
- trap 入口从旧用户 SATP 提取 ASID，返回时使用已编码 MM-owned ASID 的完整 SATP。
  非零 ASID 把用户翻译与固定内核 ASID 0 隔离，因此普通切根不再固定全刷；ASIDLEN=0
  平台仍执行原有 switch-time 全量 `sfence.vma`，不把性能优化变成兼容性前提。

**最关键的 rollover 竞态：**

- “全 CPU 已 flush 并 ack”本身还不够。如果某 CPU 在 ack 前已读取旧页表根/ASID，ack
  后再把该快照安装进 SATP，就会重新运行旧 epoch。
- 因此 RV64 `trap_return()` 明确断言 SIE 已关闭，并从 `activate_user_vm()` 取得 context
  到汇编最终 `sret` 持续保持 IRQ-off。目标 CPU 要么先带旧 context 返回，然后被 pending
  IPI 立即拉回内核、flush 后 ack；要么先 ack，之后重新取得新 epoch context。不存在
  “先 ack、后安装旧 SATP”的顺序。
- DeepSeek 的初次设计审查正确指出 SBI a4/FID 2、SATP 编码和公共 `asid_context` 三个
  接口缺口，但认为 flush 后旧快照可再次安装仍安全。GPT/Codex 按逐指令时序否决该判断，
  补上 IRQ-off 交接不变量，并把模式沉淀到 `debugging-patterns.md`。
