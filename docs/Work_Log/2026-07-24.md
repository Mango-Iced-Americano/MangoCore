## 2026-07-24

### 修复 full-test runner: QEMU 工作目录和 competition profile

**涉及文件：**
- `scripts/full_test/runner.py` — `_run_to_file()` 新增 `cwd` 参数，QEMU 调用处传入 `cwd=roles.repository / "os"`，确保 `../sdcard-*.img` 相对路径正确解析；两处 QEMU 调用（串行/并行）均使用 `competition` profile。

**根因：** Makefile 的 `qemu-profile-dry-run` 生成的 QEMU 命令中 sdcard 路径为相对于 `os/` 的 `../sdcard-rv.img`，但 Python subprocess 未设 cwd，路径从仓库根目录 `/app` 解析为 `/sdcard-rv.img`（不存在），导致 QEMU 立即 exit 1。

**修复总结（3 个 commit）：**
1. `f5b933b0` — `_extract()` 解压到 `official_x0` 路径（`../sdcard-*.img`），QEMU 用 competition profile
2. `0ffd7c0a` — 并行 QEMU 分支也改为 competition profile（漏改修复）
3. `8f3afdbe` — `_run_to_file()` 加 `cwd` 参数，QEMU 子进程 cwd 设为 `os/`

**验证：**
- `make kernel ARCH=rv64 PROFILE=normal` ✅
- `make kernel ARCH=la64 PROFILE=normal` ✅
- LA64 competition QEMU 手动测试：OpenSBI 启动成功 ✅
- full-test 双架构 QEMU 均正常启动并运行竞赛基准 ✅
