**实现思路与安全边界：**

- 先完成硬件 ID 到逻辑 ID 的映射，再取 `PER_CPUS[logical_id]`，避免

- RV64 `tp` 虽然不会被编译器分配为临时寄存器，但它同时是用户 TLS；
  LA64 `$r21` 也会被用户上下文保存/恢复。当前 trap 入口尚未重装内核
  锚点，因此本批刻意不公开运行期 `cpu_id()`，不让调度/MM 消费该指针。
- 本批不修改 trap、上下文切换、调度、PTE/TLB、锁或中断状态，不新增
  跨核可变共享关系。

### SMP-P1-B03：双架构 1/2/4/8 核最小 BSP/AP 启动闭环

**涉及文件：**

- `os/src/smp.rs` — 新增最小启动状态机、硬件 ID 到逻辑 CPU ID 的可逆
  映射、Release/Acquire 发布、online mask 和 5 秒有界等待。
- `os/src/main.rs` — `rust_main(hardware_id, boot_arg)` 分流 BSP/AP，
  原全局初始化路径收拢为 CPU0 独占的 `bsp_main()`。
- `os/src/hal/arch/riscv/{mod.rs,sbi.rs}` — 增加 SBI v0.2 BASE probe、
  HSM `hart_start` 和 AP `wfi` park。
- `os/src/hal/arch/loongarch64/{boot.rs,entry.asm,mod.rs}` — 统一入口 ABI，
  移除非零 CPU 的 bootstrap 永久自旋，并按 QEMU 9.2 slave boot ROM
  协议实现 mailbox + IPI 唤醒；2K1000LA 保持单核并明确拒绝多核启动。
- `os/src/hal/{arch/mod.rs,mod.rs}` — 导出双架构 AP start/park HAL 接口。
- `os/make/{rv64.mk,la64.mk}` — 参数化 QEMU 入口使用 MTTCG 和单
  socket/N core/单 thread 拓扑，ktest 接收同一 `CORE_NUM`。
- `docs/01_architecture/boot-and-trap.md`、
  `docs/10_plan/smp-8core-implementation.md` — 同步最小启动控制流、固件
  差异、逻辑 CPU 映射和 Phase 1 `partial` 边界。
- `docs/Work_Log/evidence/2026-07-24/smp-P1-B03-*` — 保存 RED、官方协议
  验证、构建/QEMU 矩阵、ELF 布局、判定状态和最终审计。

**为什么这样实现：**

- AP 不能进入历史 `rust_main()`：BSS、heap、frame allocator、驱动、FS
  和全局调度器都只有单份，重复初始化会直接破坏全局状态。因此 CPU0
  继续完整启动，AP 只允许使用独立 boot stack 和三个启动原子。
- 启动阶段值放入 `.data.boot`，而不是 BSS。LA64 AP 可能已经在 QEMU
  slave ROM/启动栈上等待；CPU0 的 `mem_clear()` 不能把 AP 正在观察的
  状态清零。
- CPU0 对 `BOOT_PHASE` 使用 Release，AP 使用 Acquire；AP 发布 online
  位同样使用 Release，CPU0 等待使用 Acquire。阶段值因此同时携带其前面
  初始化完成的可见性，普通整数或 volatile 不能提供该跨核关系。
- RISC-V 不能假设 hart0 是 BSP。显式 MTTCG 的 4 核测试出现 Boot HART
  2，8 核出现 1；比赛式 `-bios default -smp 8` 又出现 Boot HART 6。
  实际启动 hart 固定映射为逻辑 CPU0，其余硬件 ID 保持连续且可逆，HSM
  启动时再转换回真实 hart ID。
- LoongArch 的首次 no-op 假设被 RED 推翻：QEMU 9.2.1 官方 `boot.c`
  把 AP 放在 pflash slave boot ROM 中。CPU0 必须向
  `IOCSR_MAIL_SEND(0x1048)` 写入低 32 位物理入口，执行 `dbar 0` 后向
  `IOCSR_IPI_SEND(0x1040)` 发送 vector 0；AP 才会读取 mailbox 并跳转。
- AP online 后立即 park，且不打印。当前 console 尚未证明跨 CPU 安全，
  timer/IPI/trap 和调度器也未完成 PerCpu 改造；“可启动”不能偷换为
  “可并行运行任务”。

**RED 与根因：**

- 修改前 RV64 两核 OpenSBI 能枚举两个 hart，但只有 CPU0 输出，没有 AP
  online 标记；仅增加 Rust AP 分支不足以启动 HSM stopped hart。
- LoongArch 初版把 `start_secondary_cpu()` 实现为 no-op，两核在 5 秒后
  panic：`expected=0x3 online=0x1 missing=0x2`。根据 QEMU v9.2.1 官方
  `hw/loongarch/boot.c` 和 `hw/intc/loongson_ipi_common.c` 修正为
  mailbox + IPI 协议后通过。
- RV64 四核初版在 OpenSBI 日志后超时；日志显示 Boot HART ID=2，内核却
  硬编码物理 hart0 才走 BSP。加入硬件/逻辑 ID 映射后同一场景通过。
- QEMU 内核 panic 仍可能以进程状态 0 退出；最终判定同时要求期望 online
  标记、`KTEST RESULT: PASS`、无 `panicked at`，不把 QEMU 状态单独当绿。

**最终验证：**

**涉及文件：**

  256 KiB 启动栈；在首次设置 `$sp` 前读取并校验 `CSR.CPUID`，再按

- `docs/01_architecture/boot-and-trap.md` — 同步双架构早期启动栈现状，

  证据、双架构构建、ELF 布局/反汇编、1/2 核 QEMU 输出和行数分类。

**实现思路与不变量：**

- DMW 建立后立即读取 CPU-local `CSR.CPUID`，不在多个 CPU 间共享栈；
  `cpu_id >= 8` 时在分配 `$sp`、调用 Rust 或输出日志前原地 park。
- 合法 CPU `N` 独占
  `[base + N * 0x40000, base + (N + 1) * 0x40000)`；CPU0 的栈顶与
  原单核实现相同，整个数组大小固定为 `0x200000`。
- 使用乘法和 `BOOT_STACK_SIZE` 操作数计算步长，避免汇编位移量与 Rust
  配置分叉；`$a0` 保留为 CPU ID 传给现有 `rust_main()`。
- `.bss.stack` 仍位于 `sbss` 之前，BSP 的 `mem_clear()` 不会清零 AP
  正在使用的早期栈。
- 改动仅由 `board_laqemu` 编译；2K1000LA 继续使用原 `entry.asm`
  单核入口。本批不增加锁、原子变量或新的 `unsafe` 所有权关系。
- 本批只隔离早期栈，不使 AP online：现有 LA64 bootstrap 仍会让非零
  CPU 自旋，且 `rust_main()` 尚未拆为 BSP/AP 两条初始化路径。
