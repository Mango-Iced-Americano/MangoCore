## 2026-08-09

### 修复 FDT VirtIO-MMIO 跨类型探测重置设备导致的 RV64 启动卡死

**涉及文件：**
- `os/src/drivers/net/virtio_net.rs` — 仅在读取到 `DeviceType::Network` 后创建网卡驱动；跳过块设备时保留只读 transport，避免其 Drop 重置块设备。
- `os/src/drivers/block/virtio_blk.rs` — 对称保留跳过的网卡 transport，避免块设备枚举在 Drop 时重置已初始化的 virtio-net。
- `os/src/main.rs` — 保留 develop 的内核块设备挂载，同时将 `net::config::init()` 前移到块设备挂载之前。
- `docs/06_net/device-adapter.md` — 记录 VirtIO-MMIO FDT 跨类型探测的生命周期约束。

**验证：**
- Docker：`make kernel ARCH=rv64 PROFILE=normal` ✅（release 链接完成，2m30s）。
- Docker：`timeout 300 make -C os rv64-derived-run PROFILE=normal` ✅ 越过 VirtIO 初始化；`vda`/`vdb` 成功发现并挂载，DHCP 获得 `10.0.2.15`，PID1 与 `test-runner` 启动，读取 `/sdcard/os_test.conf` 的 `mask=0x003`。

**备注：** test-runner 后续尝试从 Alpine 镜像下载 `e2fsprogs` 时 DNS 临时失败，因此 basic/busybox 未实际开始；该失败发生在用户态包下载，已不再是内核 VirtIO 启动阻塞。所有临时 `[debug]` 输出已移除。
