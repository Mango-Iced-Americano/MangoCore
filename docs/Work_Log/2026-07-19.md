### 补齐 lwext4 journal 的设备 flush 与持久化顺序

**涉及文件：**
- `os/src/drivers/block/{block_dev,partition,sata_blk,virtio_blk,virtio_blk_pci}.rs` — 为通用块设备增加可失败的 `flush()`，由 SATA、VirtIO 及分区/块大小/只读包装层向物理设备透传
- `os/src/fs/ext4_lwext4/blockdev.rs`、`dependency/lwext4_rust/src/{blockdev,bindings}.rs` — 打通 Rust → C → Mango 块设备的 flush ABI，并规范化正负 errno
- `dependency/lwext4_rust/c/lwext4/{include/ext4_blockdev.h,src/ext4_blockdev.c}` — 增加可选物理 flush 回调；软件 block cache 排空后继续建立真实介质持久化边界
- `dependency/lwext4_rust/c/lwext4/{include/ext4_journal.h,src/ext4_journal.c,src/ext4.c}` — 建立 journal record → commit → home block → tail 的有序 flush，传播 checkpoint/stop/recovery 失败
- `os/src/kernel_tests/ext4.rs`、`os/make/{rv64,la64}.mk` — 增加包装链 flush 透传测试，并允许 fixture 显式启用 `has_journal`
- `.agents/skills/mango-workflow/references/harness-patterns.md` — 沉淀 journal durability 门禁与 fixture 特性证明方法

**备注：**
- 持久化顺序为：descriptor/data/revoke 写入 → device flush → commit block 写入 → device flush → checkpoint/home blocks 写入 → device flush → journal tail 前移。恢复路径则先让 replayed home blocks 和主 superblock 落稳，再写并 flush 清理后的 journal superblock。
- 这次关闭的是“正常 journal 提交/恢复/卸载缺少设备 barrier”缺口。验证覆盖正常卸载和同镜像再挂载，但尚未执行事务中途强制断电的 replay 注入测试，因此不能把结果扩大为完整 power-loss 证明。
- 新实现仍没有 ext4 persistent orphan list / mount-time orphan cleanup；运行期 open-unlink 句柄语义不等于崩溃后 orphan 可回收。orphan 门禁继续保持 RED，生产 P4 写测试仍未放行。
- SATA 现有 `write_block()` 仍逐写执行 cache flush，本次没有顺带改变其性能策略，避免把 durability 修复与实板写合并优化混在同一提交；后续需在独立性能任务中评估由 journal barrier 批量提交替代逐块 flush。
