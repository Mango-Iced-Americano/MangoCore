- SATA 现有 `write_block()` 仍逐写执行 cache flush，本次没有顺带改变其性能策略，避免把 durability 修复与实板写合并优化混在同一提交；后续需在独立性能任务中评估由 journal barrier 批量提交替代逐块 flush。

- `dependency/lwext4_rust/src/{bindings,blockdev}.rs`、`os/src/fs/ext4_lwext4/ext4fs.rs` — mount 时在 journal replay 后、开放写入前执行 orphan cleanup，并保持失败路径生命周期可回滚
- `os/src/kernel_tests/{ext4,mod}.rs`、`os/make/{rv64,la64}.mk` — 增加“首启制造 power cut、次启复用原镜像恢复”的测试组，以及镜像复用、block size、post-fsck 控制

**验证：**
- 修复前 RV64 同类掉电镜像经只读 `e2fsck -f -n` 报 `Deleted inode 12 has zero dtime`、block bitmap `-2065`、inode bitmap `-12`，`e2fsck_exit=4`，证明旧实现会泄漏 zero-link inode/block，RED 成立 ✅
- RV64 4 KiB ext4：首启在 journal commit 已持久、home checkpoint 未开始的窗口由外部 timeout 截断；次启复用同一镜像，mount cleanup 恢复恰好 1 个 orphan，旧路径不存在，写/读/删除探针通过，teardown 与五阶段 fsck 干净 ✅
- LA64 4 KiB ext4：同样完成两阶段 crash/recover，恢复恰好 1 个 orphan，teardown 与 fsck 干净 ✅
- RV64 1 KiB ext4：同样完成两阶段 crash/recover，覆盖 ext4 superblock 位于逻辑块 1 的 replay 边界，teardown 与 fsck 干净 ✅
- 常规 `KTEST=ext4` 回归在 RV64、LA64 均 8/8 通过，teardown 与离线 fsck 干净；最终源码又顺序完成 RV64、LA64 kernel build，其中 LA64 精确最终构建日志为 `la64-lwext4-orphan-final-build.log` ✅
- `git diff --check` 通过；所有可写实验均在 Docker/QEMU disposable image 中完成，生产实板 SSD P4 未挂载、未写入 ✅

**备注：**
- 旧代码只保证“内核仍运行时”的 open-unlink：open count 和待回收状态都在内存，突然掉电后没有可 replay 的恢复意图。新代码把 namespace detach、zero-link inode 和 persistent orphan chain 纳入 journal，mount 时先严格预校验再逐项 truncate/free，恢复可重试并对损坏链 fail closed。
- mount cleanup 先线性预校验、随后只移除链头，整体为 O(n)；orphan add/del 的链维护仅与同时存在的 zero-link open inode 数量相关。普通 read/write 快路径不变，但每次 link count 归零会多写 inode 与 superblock journal metadata，这是换取 crash consistency 的必要成本。
- 当前实现使用 Linux 兼容的 legacy orphan list，不支持 `orphan_file` incompat feature；测试 fixture 显式使用 `^orphan_file`。实板 writable mount 前必须先只读检查目标卷 feature，遇到 `orphan_file` 应拒绝而不是降级写入。
- SATA `write_block()` 仍逐块 flush，其吞吐优化不属于本次正确性提交；后续应单独基准 journal barrier 批量化，不能用删除持久化边界换性能。
- 本轮关闭了 QEMU 强制掉电与双架构恢复门禁，但生产 P4 仍未放行写入；下一步实板应先使用独立 scratch 分区/可恢复副本验证，再决定是否进入生产分区。
