## 2026-07-28

### 修正 VF2 GMAC0 平台时钟与复位序列

**涉及文件：**
- `os/src/drivers/net/gmac_jh7110/mmio.rs` — 区分 GMAC0 GTX 与 GTXCLK 寄存器，补充 PTP、GTXCLK、TX 反相位和四步复位常量。
- `os/src/drivers/net/gmac_jh7110.rs` — 在 DMA 初始化前写入已验证的 PTP/GTX/GTXCLK、TX 时钟及 TX 反相位配置，并以 100ms 间隔执行 `0xe1 -> 0xe3 -> 0xe2 -> 0xe0` 复位序列。
- `os/src/drivers/net/gmac_jh7110/ktest.rs`、`os/src/kernel_tests/gmac.rs` — 增加平台时钟/复位 readback 契约，覆盖 AHB/AXI gate、TX、TX inversion、PTP、GTX、GTXCLK 与最终 reset 状态。

**验证：**
- Docker 内 `make toolchain-preflight` ✅。
- Docker 内 `make ktest-build-only ARCH=rv64 PROFILE=normal BOARD=vf2 KTEST=gmac` 在新增 readback 字段前按预期 RED（10 个 `E0609`），补齐字段与驱动序列后 GREEN ✅。
- Docker 内 `make kernel ARCH=rv64 PROFILE=normal` ✅。
- Docker 内 `make kernel ARCH=la64 PROFILE=normal` ❌：`os/src/hal/arch/mod.rs` 从 `loongarch64` 导入 `reboot`，但 `os/src/hal/arch/loongarch64/mod.rs` 未重导出已有的 `sbi::reboot`；该缺陷已存在于 `HEAD` 的 `acef5d94`，不属于本次 VF2 修改。
- Docker 内 `make lint` ❌：在 `rv64/debug` 既有 warning 基线漂移处停止（`src/drivers/rng/mod.rs`、`src/fs/ext4/bitmap.rs`），未报告本次 GMAC 文件；容器缺少 `cargo-fmt`，无法运行 `cargo fmt --check`。
- VF2 实板 RAM-only ktest已执行：CRC XMODEM-1K 传输 4,753,720 字节镜像并收到 EOT ACK；`gmac::platform_clock_reset_state`、`tx_submitted`、`tx_own_cleared`、`rx_dma_running`、`rx_mac_config_ok` 通过，结果为 5/8。`tx_healthy` 报 DMA `TBU`（`DMA_STATUS=0x00000404`），RX 无 writeback，关闭后的 `eth1` ARP pcap 为零帧；正在以 TX tail pointer、DMA cache 可见性和协商速率时钟三条假设进行第二轮根因确认。

**备注：** 本轮只合入 StarryOS VF2 源码直接证实的平台初始化差异；未修改 PHY、RX 反相位、协商后速率、DMA cache maintenance、U-Boot 或 2K1000 驱动。未命中需同步的子系统 `code_paths` 文档；AI 使用报告无需更新。缓存维护仍需 MangoCore HAL 与实板 RED 证据后另行处理。
