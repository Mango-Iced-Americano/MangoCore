### SMP-P2-B11：timer hard IRQ 与 deferred 安全点分离

**范围与根因：**

- CPU0 原 timer IRQ 会持 timer/task/network 路径中的普通锁、执行 callback，
  并可能直接 context switch。若为 AP→BSP、shootdown 或 STOP 在长 syscall
  中打开内核中断，这条旧路径可在任意内核位置调度，破坏锁和栈不变量。
- 本包只建立 timer hard/deferred 边界，不提前启用 CPU0 IPI、不让 AP 运行
  timer，也不混入 STOP、RESCHEDULE、runqueue 或 TLB。

**实现与并发语义：**

- `PerCpu` 增加 timer pending、hard IRQ 次数和 deferred 批次计数。hard IRQ
  只静默本地 one-shot、执行原子诊断计数并以 Release 发布 pending；
  多次 IRQ 可以合并，因为软件 timer 与调度 tick 都基于绝对 deadline。
- RV64 通过 SBI 把 timer compare 写到 `usize::MAX` 清 pending；LA64
  对 TICLR 执行 W1C，非周期 TCFG 到零后保持停止。两架构均由安全点按完整
  timer queue 重编程下一次事件。
- 旧 kernel timer、legacy timeout、timerfd、网络 poll 和调度判定移动到
  `run_deferred_timer_work()`。`trap_return()` 在信号处理前调用任务安全点，
  scheduler 在取得 Processor/ready queue 锁前调用 idle 安全点；完整处理
  期间保持本地中断关闭，最后才在显式边界决定是否让出 CPU。
- 审计发现旧 `record_timer_interrupt()` 达到阈值时会在 IRQ 中
  `print_snapshot()`。本包把 hard path 收敛为纯原子计数，并用原子 epoch
  将周期性快照去重后移到 deferred 安全点，避免诊断旁路重新引入 console 锁。
- 新 focused test 连续执行两轮真实内核 timer IRQ：先证明 IRQ 到达后
  deferred 计数未动、pending 已发布且当前 TID 不变，再显式消费安全点并
  证明恰好完成一批；第二轮同时验证 one-shot 已成功重编程。

### SMP-P2-B10：通用 IPI reason 与 BSP→多 AP 广播

**范围与依赖审计：**

- 原目标包含 AP→BSP PONG。实现前检查发现 CPU0 已打开 timer，而双架构
  内核 trap 尚未把 timer 改成只记原子状态的 deferred handler；此时为了
  接收 PONG 打开内核中断，会重新暴露“任意内核位置从 timer IRQ 直接调度”
  的旧路径。因此本包没有增加测试专用 timer 屏蔽窗口，而是收窄为通用
  reason API 和 CPU0→全部 AP 广播。
- AP→CPU0、交叉发送和真正 ping-pong 被明确放到 deferred timer 之后，
  不是以本次广播结果外推为已经支持。

**实现与并发语义：**

- 新增 `IpiReason`，把 mailbox 的语义固定为可合并的幂等 reason bit；
  它只承诺“至少处理一次”，计数协议必须另带 sequence/ack。
- 新增 `send_ipi_mask()` 和单目标包装。发送广播时先用 Release 发布全部
  目标 mailbox，再逐个触发硬件 doorbell，为整轮建立统一的
  “publication before delivery”批次边界；每个 AP 仍只读取本地 mailbox。
- 若某个 doorbell 失败，仍继续通知本轮其余目标并在最后返回首个错误。
  失败目标的 reason 保留，不能对已经并发可见的原子状态做不安全回滚。
- focused ktest 先快照三个 AP 各自的下一 ack，再使用一个共同的一秒期限
  等待全部完成；这样既验证独立 per-CPU ack，也避免每个目标各自延长超时。

### SMP-P2-B09：双架构最小 IPI mailbox/ack 闭环

**范围与设计：**

- 本包只建立 BSP→AP 的单播 PING，闭合
  `Release mailbox → hardware doorbell → kernel trap → Acquire consume
  → Release ack`。不混入 timer、STOP、RESCHEDULE、runqueue 或 TLB，
  使第一次跨核中断的故障边界保持可审查。
- `PerCpu` 增加 `pending_ipi` 和 PING ack，并为各字段补充中文所有权与
  状态语义注释。reason 是可合并 bitset，不是事件队列；测试串行等待
  前一次 ack 后才复用同一 bit。
- handler 只执行原子操作，不分配、不打印、不获取普通锁、不直接调度。
  AP 仍不进入旧调度器，只从永久 park 升级为 IPI-only idle loop。

**双架构实现：**

- RV64 通过 SBI v0.2 IPI extension 发送 doorbell，使用
  `hart_mask=1, hart_mask_base=目标硬件 hart`，不依赖 logical ID 与
  OpenSBI hart ID 恒等。AP 只打开 SSIE；新的 `__kern_trap` 保存全部可见
  GPR、原始 `sp`、`sstatus` 和 `sepc`，清 SSIP 后处理 mailbox。
- LA64 QEMU 运行期使用 IOCSR vector 1，与 slave boot ROM 的启动
  vector 0 分离。AP 只打开 IPI line；内核 trap 在读取 BADV/打印诊断前
  先清 level-triggered source 并走 mailbox fast path。
- 两架构 trap 返回后分别回到 `wfi`/`idle 0`，等待下一次 doorbell。
  2K1000LA 仍按计划保持单核，运行期发送接口明确返回不支持。

**规范依据：**

- RISC-V SBI 规范定义 IPI extension EID `0x735049`、FID 0，并规定目标
  supervisor 以 SSIP 观察 IPI；
- LoongArch 架构手册规定 IPI 为 line-based interrupt；Loongson IPI
  控制器以 `CORE_CLEAR` 写 1 清状态；
- QEMU LoongArch IPI 实现确认 `CORE_ENSET/CORE_CLEAR/IPI_SEND` 的
  IOCSR 偏移及 doorbell 目标编码，slave boot ROM 在跳转内核前清启动
  vector 0。

**Docker 验证：**

- RV64 `CORE_NUM=2 KTEST=smp`：退出 0，`online_mask=0x3`，4/4 PASS；
- LA64 `CORE_NUM=2 KTEST=smp`：退出 0，`online_mask=0x3`，4/4 PASS；
- 两个入口均包含实际编译、链接和 QEMU，严格串行执行；没有额外重复
  build-only、单核或 4/8 核矩阵。
- 可提交的确定性摘要位于
  `docs/Work_Log/evidence/2026-07-25/smp-b09-summary.md`。

**阶段结论：**

- `SMP-P2-B09=pass`，证明双架构 BSP 能通过真实硬件/固件 IPI 唤醒 AP，
  内核 trap 可安全返回 idle loop；
- 整体 Phase 2 仍为 `partial`：广播、交叉发送、并发 reason、STOP、
  10,000 次 ping-pong、deferred timer 和长 syscall 中断窗口尚未完成；
- 本包未发现需要沉淀为通用 debugging/performance reference 的新模式；
  mailbox 内存序、trap frame 和运行期 vector 所有权已同步到架构文档与
  实施方案。

### SMP-P1-B08：AP 切换独立 idle stack 后再发布 online

**范围与撤销：**

- 先完整撤销未提交的 B07 validation-only patch。该 patch 只增加全局初始化
  计数和栈地址 probe，没有建立新的运行期能力，还会让启动主链被验证代码
  打断，因此不保留。
- B08 改为闭合一个真实启动不变量：AP 完成本地 bootstrap 后必须离开
  firmware boot stack，在 logical CPU 独占的 idle stack 上发布
  `idle=true`，随后才允许发布 `online=true`。

**实现与理由：**

- 双架构 HAL 按构建期 `configured_cpu_count()` 分配页对齐的静态 idle
  stack；RV64 每槽 64 KiB，LA64 每槽 128 KiB。只分配 configured 数量，
  避免单核实板承担 8 核静态内存成本。
- idle 区使用 `.bss.idle_stack`，由链接脚本既有 `.bss.*` 通配符放在
  `sbss..ebss`。它与正在参与 BSS 清零的 boot stack 生命周期不同：AP
  观察 `BOOT_PHASE` Acquire 前不会使用 idle 区，因此应由 CPU0 正常清零；
  同时该区仍在 `skernel..ekernel` 内，不会被 frame allocator 回收。
- 双架构新增发散的 naked trampoline。标准 C ABI 把 logical ID、栈顶和
  Rust 入口分别放入 `a0/a1/a2`；汇编只更新 `sp`、断开旧 frame/return
  链并间接跳转，刻意保留 RV64 `tp` / LA64 `$r21` 的 PerCpu 指针。
- `PerCpu` 新增 `idle: AtomicBool`。AP 在新栈上的第一个 Rust 入口先校验
  `cpu_id()`，以 Release 发布 idle，再通过既有 Release CAS 发布 online；
  BSP Acquire 观察 online 后即可依赖 AP 已完成切栈。CPU0 保持
  `idle=false` 并继续独占旧调度器。
- `KTEST=smp` 新增 AP idle context 断言。该状态不是一次性测试 probe，
  Phase 2 会继续把它用于 idle/远程唤醒协议。

**官方规范与独立审查：**

- RISC-V psABI 与 LoongArch ELF ABI 均要求标准过程入口的 `sp` 维持 128-bit
  对齐；两架构页对齐基址和页倍数槽宽满足该约束。Rust Reference 要求
  naked body 完整承担 ABI 并明确返回或发散，本实现签名为 `-> !` 且不
  fall through。
- DeepSeek 以只读方式自主审查当前 diff 和双架构日志，结论为没有必须修的
  缺陷、现有 focused 证据已经足够，应停止追加测试并转入 IPI/可唤醒 idle
  功能。其建议把 timer、runqueue、页表一起纳入下一包会扩大并发范围，未
  直接采纳；下一包应先闭合最小 IPI mailbox/ack 协议。

**Docker 验证：**

- RV64 `CORE_NUM=8 KTEST=smp`：`boot_hw_id=6`、
  `online_mask=0xff`，3/3 PASS；真实覆盖非 hart0 冷启动映射和 7 个 AP
  idle stack 切换。
- LA64 `CORE_NUM=8 KTEST=smp`：`boot_hw_id=0`、
  `online_mask=0xff`，3/3 PASS。
- 最终 ELF 反汇编确认 RV64 为
  `mv sp,a1; li s0,0; li ra,0; jr a2`，LA64 为
  `addi.d sp,a1,0; addi.d fp,zero,0; addi.d ra,zero,0; jr a2`。
  `IDLE_STACKS` 均为页对齐 BSS 符号并位于 `sbss..ebss`。
- 未重复执行独立 build、单核或用户态全量回归：双架构 8 核 focused ktest
  已包含实际编译、链接和本工作包唯一改变的 AP 路径；CPU0 调度不变量也在
  同一次运行中覆盖。

**阶段结论：**

- `SMP-P1-B08=pass`；AP 的 online 现在承诺“已在独立 idle stack 上”，
  而不再只是“bootstrap 已返回”。
- 整体 Phase 1 仍为 `partial`：可唤醒 idle loop、内核 trap/IPI、
  console 多核串行化和其余 PerCpu 字段尚未完成。
- 本批没有新增独立 debugging/performance reference；启动栈生命周期和
  online 发布顺序已同步到启动架构文档与 SMP 实施方案。
