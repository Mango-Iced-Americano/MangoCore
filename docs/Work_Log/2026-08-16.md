## RV64 第三轮性能包：定点时间换算、CBO.ZERO、更大 readahead/prezero、QEMU gate fence.i

**Date:** 2026-08-16 +08:00
**Author:** AI:Codex | Human:lzm
**Tags:** [area:riscv64, area:mm, area:timer, area:scheduler, area:buildstorm, type:performance, type:validation]
**Mango Gate:** skill loaded=yes; references=harness-patterns.md

**Summary:** 在 `rv-satp-fix` 合入 `main` 最终修复后，实现并验证一组 RV64
BuildStorm 优化。production 干净 BuildStorm 从同口径 1862s 降至
**1784s（-78s，-4.19%）**；`[axbuild]` 计时段从 1814.00s 降至
**1736.32s（-77.68s）**。仍慢于官方 RV B=1616s 参考线 168s（10.4%），
但本轮是固定窗口之外首个在完整计时段稳定复现的正向包。

**Changes:**
- `os/src/timer.rs` — `ticks_to_ns/us/ms` 与 `ns_to_ticks_ceil` 改为一次预计算
  `u64 fixed-point` 倍率；RV64 不再在每条 trap 时间记账路径调用 `__udivti3`。
- `os/src/hal/arch/riscv/{mod.rs,trap/mod.rs}`、`os/src/mm/frame_allocator.rs` —
  FDT 全部 CPU 报告 Zicboz 时页清零使用 `cbo.zero`；平台信息发布前仍保持标量清零，
  能力缺失平台 fail-closed。trap-return `fence.i` 按平台模型门控：QEMU TCG 默认
  省略，真实硬件/未知平台默认执行，`mango.rv.trap_return_fence_i=on|off` 可覆盖。
- `os/src/fs/page_cache.rs`、`docs/09_debug/perf_diag.md` — demand read 窗口
  16→32 页（64→128 KiB）。
- `os/src/mm/frame_allocator.rs` — prezero 高水位 256→2048 页，idle tick 补充
  2→8 页，event wake 补充 32→128 页。
- `os/src/task/{manager,processor}.rs` — scheduler tick 10ms→20ms，文档同步。
- `os/Cargo.toml` — release 增加 `codegen-units = 1`、`panic = "abort"`。

**Verification:**
- 双架构 production `cargo check` — ✅。
- RV64 `KTEST=timer,smp` 42/42、`KTEST=timer,smp,page_cache_sync` 50/50 — ✅。
- Docker `make lint` 四格 — ✅（RV 190/0/30，LA 192/0/31）。
- production 完整 BuildStorm（同官方 golden、RV8/8 GiB/MTTCG、LOG=off、无
  `perf_diag`）— ✅，`BUILDSTORM_COMPILE ok=true elapsed_s=1784.00`，完整 END，
  panic/exception/OOM/BadAddress/shootdown timeout 扫描无匹配。
- 同镜像 bootarg `mango.rv.trap_return_fence_i=off` 先行样本 — ✅ 1818s；
  默认策略改为 QEMU gate 后的正式样本 — ✅ 1784s。

**Notes:** 单样本 78s 改善仍受历史 BuildStorm 噪声（±30s 量级）影响，但方向与
固定窗口 `task_run_slice` 增量、`frame_prezero_refill_ticks` 减半一致。官方基线
1616s 的剩余缺口主要在 8 核 TCG 下 `core`/`std` 长串行段与后续大量中小 crate；
后续候选应优先评估 trap FPU lazy save、文件映射 fault-around 上限再提高、以及
Cargo 并行段 scheduler wake/steal 时延。
