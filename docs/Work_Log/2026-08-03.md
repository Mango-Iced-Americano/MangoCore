### 修复：PageCache miss run 分批读取以约束 staging 内核堆分配（消除 26 MiB 堆 OOM）

**背景：** 实板 buildstorm rustc 编译时触发 `layout: size=27262976, align=1`、`KERNEL_HEAP_SIZE=33554432`（rv64 32 MiB 堆）。父级 + Oracle 分析定位为 PageCache 读路径：一次跨 26 MiB 的连续读把全部未缓存页合并成单个 6656 页 miss run，`fill_miss_runs` 把整个 run 一次性交给 `backend.read_pages()`，后端（`AnotherExt4PageCacheBackend`）分配 `Vec<u8>` 长度 = `pages.len() * PAGE_SIZE` = 26 MiB staging；buddy 四舍五入到 32 MiB（order 25），在 rv64 约 31.8 MiB 可用堆上必然失败。smaps 修复（`af9900be`）未触及此路径，故问题依旧。

**复现（RED→GREEN 门禁）：** 新增 ktest `ext4_another::large_miss_run_read_does_not_oom`（`os/src/kernel_tests/ext4_another_lifetime.rs`）：在 clean-ext4 ktest 镜像上创建 27 MiB 文件，按 64 KiB 分块有界写入（写路径不触发 OOM）→ sync → `invalidate_range(0, 6912)` 逐出整段 → 单次读 26 MiB 使 `lookup_read_range_fast` 合并出 6656 页 miss run。未修复代码在 ktest QEMU 中稳定崩溃 `layout: size=27262976`（RED）；修复后 5/5 通过且 26 MiB 逐字节 pattern round-trip 一致（GREEN）。目标缓冲区用 `static mut` BSS（不用堆：26 MiB 请求同样会被 buddy 取整到 order 25 而失败，会掩盖后端 staging OOM）。

### 修复：procfs smaps 改为 per-open 有界游标流式输出（消除多 MiB 内核堆快照 OOM）

**背景：** libc-bench `b_pthread_create_serial1`（约 2500 线程、约 5000 个 VMA）读 `/proc/self/smaps` 时，旧实现（commit `3f4f40ae` 引入的 text_fn 缓存快照路径）在每次 open 时构建一份完整的 smaps String（`String::with_capacity(user_vma_count * 256)`，实际增长到 2,562,560 字节 → buddy 四舍五入到 4 MiB）。在 32 MiB rv64 静态堆 + 碎片化条件下触发 `HEAP ALLOCATION FAILED (FATAL)`。fingerprint：2562560/2/256 = 5005 VMAs。

### RV64 网络死锁修复：syscall 上下文 VirtIO egress 延迟发送

**涉及文件：**
- `os/src/net/socket/inet/datagram/udp.rs` — 删除 `UdpSocket::new()` 中多余的 `NET_INTERFACE.poll()`（socket 创建不需要网络 I/O）。
- `os/src/net/adapter.rs` — `NetTxToken::consume()` 增加中断状态判断：SIE=1 走原阻塞发送；SIE=0（syscall/trap 上下文）把数据包放入延迟发送队列。
- `os/src/net/config.rs` — 新增全局 `DEFERRED_TX_QUEUE`（独立于 `NET_INTERFACE.inner` 锁，避免锁重入死锁）+ `push_deferred_tx()` + `poll_once()` 内 drain 逻辑（调度器上下文中断开启时真正发送）。
- `os/src/hal/{mod.rs,arch/mod.rs,arch/riscv/sbi.rs,arch/loongarch64/{mod.rs,sbi.rs}}` — 新增 `hal::irq_enabled()`：riscv 读 `sstatus.sie()`，la64 读 `CrMd::read().is_interrupt_enabled()`。
- `os/src/task/perf.rs` — 新增 `record_net_tx_deferred_dropped()` 计数器（含 noop 版本与 `NET_TX_DEFERRED_DROPS` 原子）。

**根因：** syscall trap 上下文（SIE=0）调用 `NET_INTERFACE.poll()` → smoltcp DHCP egress → VirtIO `add_notify_wait_pop()` 忙等 used-ring completion。单核上中断被禁，completion 永远不会到达 → 死循环。触发点：ntpd 创建 UDP socket。

**验证：**
- `make kernel ARCH=rv64 PROFILE=normal` ✅
- `make kernel ARCH=la64 PROFILE=normal` ✅（串行）
- `make -C os rv64-run ARCH=rv64 PROFILE=normal`（competition，之前稳定复现卡死）✅：越过 `synchronizing clock` → DHCP lease restart → ntpd fallback → LTP 5 用例 → `run_selected_groups done` → 正常 shutdown，exit=0
- 双架构 `cargo check` ✅

**备注：** 延迟队列独立锁是关键——初版把队列放在 `NetInterfaceInner` 里，`push_deferred_tx` 二次 `inner.lock()` 造成重入死锁（smoltcp poll 已持有 inner 锁）。改为全局 static 队列后解决。DHCP/ARP/TCP 协议有重传计时器兜底，延迟发送不破坏语义。
