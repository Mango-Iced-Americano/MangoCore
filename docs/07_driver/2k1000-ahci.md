# 2K1000LA AHCI 驱动

## I/O 粒度

内核块设备逻辑块为 2 KiB，ATA 逻辑扇区为 512 B。PageCache/ext4 会把物理连续页
合并成一次最多 256 KiB 的 `BlockDevice::read_block/write_block` 调用。旧 SATA
包装层却再次按 512 B 拆分，每个扇区分别执行一次轮询式 `READ/WRITE DMA EXT`：

```text
PageCache 256 KiB request
  -> SataBlock 512 x 512 B chunks
    -> 512 command setup + PxCI poll + completion checks
```

当前驱动在控制器初始化时永久取得一个 64 KiB、物理连续且低于 4 GiB 的 DMA
槽位。`SataBlock` 只按槽位大小切分，AHCI 为每个切片设置一个 PRDT 项和真实 ATA
扇区数。因此最大 PageCache 请求只需 4 条命令，64 KiB 及以下请求只需 1 条。

这里不照搬 VirtIO 的四槽状态机。`SataBlock` 的控制器由 `Mutex` 串行保护，任何
时刻只有一个在途命令；多槽不会提高并发度。单槽常驻复用保留了 DMA 池化的关键
性质：启动早期一次性分配连续内存，I/O 热路径不分配、不释放，也不会受后续物理
内存碎片影响。

## 边界与所有权

- `Provider::AHCI_MAX_TRANSFER_SECTORS` 默认仍为 1，只有 2K1000LA Provider
  显式提高到 128，避免改变其他平台语义。
- DMA 槽位通过 `frames_alloc()` 从单一 DRAM region 取得连续 extent，不能用多次
  单页分配假定物理连续。
- 整个 extent 必须落在 `0x0000_0000..0xffff_ffff`，符合当前 HBA DMA mask。
- 一个 PRDT 项最多表示 4 MiB；ATA 48-bit DMA 命令的非零扇区数还必须能放入
  `u16`。构造和每次 I/O 都检查长度、512 B 对齐与完整 LBA 末端。
- `IDENTIFY DEVICE` 仍只传输 512 B；`FLUSH CACHE EXT` 使用零 PRDT 项。
- 写路径在全部切片完成后执行一次 cache flush。AHCI drop 按真实槽位长度归还每页。

## 实板性能

环境：龙芯星云 2K1000LA，LA264 500 MHz，TS32GMTS400 32 GB SSD，commit
`85314659` 基线；所有数字均来自相同 P3 CPython 文件和同一 shell `time` 命令。

| 项目 | 512 B/命令基线 | 64 KiB 常驻槽 | 变化 |
|---|---:|---:|---:|
| `python3 -S -c pass` 热启动 | 1.925 s | 1.714 s | -11.0% |
| `python3 -c pass` 热启动 | 2.385 s | 2.175 s | -8.8% |
| 首次顺序读 `libpython` 5.48 MiB | 13.5 MB/s | 18.6 MB/s | +37.8% |
| PageCache 命中顺序读 | 约 108 MB/s | 约 108 MB/s | 无变化 |
| `import json,ssl,hashlib,pathlib` | 18.322 s | 17.993 s | -1.8% |

将槽位试验性扩大到 256 KiB 后，首次顺序读仍为 18.6 MB/s，Python 无缓存启动和
重导入也无可测改善。因此最终保留 64 KiB，避免无收益地永久占用额外 192 KiB
连续低端物理内存。

重导入仅小幅改善并不否定 DMA 修复：无缓存导入约 11.6 s 是用户态解析/编译
`.py` 的 CPU 时间。启用 P4 持久 pyc 后，相同导入稳定在约 4.495 s；该优化见
`docs/08_testing/cpython-isolated.md`。

## 验证

- rv64、la64 内核串行编译通过；两架构 QEMU 均启动、挂载文件系统并连续执行多批
  LTP 用例，无本次 AHCI API 改动导致的回归。
- 2K1000LA 通过 P2 scratch 自动写入冒烟和 P4 应用根复用门禁。
- 实板将 1 MiB 随机数据以 64 KiB 写入 P4，`sync` 后源/目标 SHA-256 一致，
  `cmp` 返回 0，再删除并同步。
- 64 KiB 与 256 KiB 两版均完成 TFTP 长度、CRC32、`iminfo` 和 uImage checksum
  校验；最终代码选择 64 KiB。
