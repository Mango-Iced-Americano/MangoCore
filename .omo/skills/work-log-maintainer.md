# Work Log Maintainer

## 触发条件
- 用户说"更新工作日志"、"记录一下"、"写进 work log"
- 每次修改代码后自动追加
- 用户说"整理工作日志"、"work log 规范化"

## 规范（MUST FOLLOW）

### 文件位置
- **唯一权威文件**：`Doc/Work_Log.md`
- 根目录 `WORK_LOG.md` 仅作为指针，写入一行 `## 工作日志已迁移至 Doc/Work_Log.md`

### 格式规范

```markdown
# 工作日志

> 维护规范：每日一个 `## YYYY-MM-DD` 标题，降序排列。
> 同一天多项工作合并在同一日期标题下，各用 `### 简短标题` 分隔。
> 每条目包含：涉及文件、根因/背景、修复/内容、验证结果。

---

## YYYY-MM-DD（最新）

### 任务简短标题（如：修复 xxx Bug）

**涉及文件：** `path/to/file.rs`

- 背景/根因描述
- 修复/内容描述
- 关键决策说明

**验证：** ✅ 编译通过 / QEMU 测试通过

### 另一任务简短标题

**涉及文件：** `path/to/other.rs`

- ...

**验证：** ✅

---
```

### 关键规则

1. **每日一个日期标题** — 同一天多项工作不拆成多个 `## 2026-XX-XX`，合并在一个标题下用 `###` 分隔
2. **降序排列** — 最新日期在最上面
3. **条目模板**：
   - `### 简短标题`（一行，十几字以内）
   - `**涉及文件：**` 列出所有修改文件（`- ` 缩进列表）
   - 叙述段：背景 → 根因 → 修复 → 关键决策
   - `**验证：**` 结尾（编译/QEMU/审查）
4. **去重** — 合并前先检查是否已有相同条目的不同版本，保留更完整的版本
5. **日期分隔** — 每天之间用 `---` 分隔
6. **不写废话** — 不写"今天做了什么"的流水账，每条目本身就是独立完整的修改记录

### 合并流程

1. 读取当前 `Doc/Work_Log.md`
2. 解析出新条目
3. 若当天已有标题 → 追加 `###` 在其后
4. 若当天无标题 → 在正确位置（降序）插入新 `##` 标题
5. 写回文件
