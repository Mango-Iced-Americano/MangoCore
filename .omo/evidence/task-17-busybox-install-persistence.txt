Task 17 busybox performance regression guard

Current architecture:
- DirtyBlockDevice re-enabled as metadata write-coalescing layer (block_device = dirty_bd).
- This provides O(1)-style batching for metadata-heavy operations like busybox --install.
- Without DirtyBlockDevice, each metadata write (directory entry, inode table, bitmap) hits
  real disk immediately, causing massive write amplification.

QEMU test results:
- busybox --install -s /bin: exit=0 (completes successfully).
- With DirtyBlockDevice removed (T14 direct-write), busybox install was too slow
  and QEMU timed out at 300s.

Performance guard:
- DirtyBlockDevice is retained as a transitional metadata write-coalescing buffer.
- File data writes for regular files use PageCache with real_block_device writeback (T12).
- sync_fs() flushes all layers: BlockCache → real device, dirty_bd → real device, PageCaches → real device.
- This is NOT the final architecture; it's a correctness-first transitional state.

Build: rv64 PASS, la64 expected to PASS.
