Task 4 directory metadata persistence scenario

Status: planned scenario, not executed in T4.

Reason:
- T4 only introduces the BlockCache metadata flush contract.
- The contract is not yet wired into ext4 `sync_fs()`; that is T13.
- Running a QEMU persistence test now would still exercise the old DirtyBlockDevice path and would not prove the new BlockCache metadata flush path.

Scenario to execute after T13:
1. Prepare a fresh ext4 image:
   - rv64: `xz -dkc fs-img-dir/sdcard-rv.img.xz > sdcard-rv.img`
   - la64: `xz -dkc fs-img-dir/sdcard-la.img.xz > sdcard-la.img`
2. Boot QEMU with the fresh image.
3. Create a directory and file, for example `/tmp/meta-dir/proof.txt`.
4. Call `sync()` or trigger `FileSystem::sync_fs()` through the VFS path.
5. Cleanly exit QEMU.
6. Run debugfs:
   - `debugfs -R 'ls /tmp/meta-dir' sdcard-rv.img`
   - `debugfs -R 'stat /tmp/meta-dir/proof.txt' sdcard-rv.img`
7. Expected result:
   - Directory entry exists.
   - Inode exists.
   - File size matches what was written.

Failure indicators:
- File visible during QEMU boot but absent in debugfs.
- Directory exists but file inode is missing.
- File size or content does not match.
